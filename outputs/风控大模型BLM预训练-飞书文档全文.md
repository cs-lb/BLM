# 一、项目背景

## 业务挑战

从需求提出到模型上线通常需要数周甚至数月的漫长周期，运营团队过度依赖算法团队且缺乏自主调优能力，需求变更频繁时重新训练成本高昂，算法团队和运营团队职责边界模糊、协作效率低下，缺乏标准化的能力输出和快速配置机制，导致业务方需求响应速度成为商业化发展的瓶颈，无法满足商业化业务的敏捷性要求。

<whiteboard token="QZBVwZRDzhUsn3bagoscj7bsnMx"></whiteboard>

当前每个新产品需求都需要算法团队从零开始训练专门模型的点对点开发模式，导致相似的内容安全能力在不同项目中被反复开发，算法工程师大量时间消耗在重复性工作上，不仅开发成本居高不下、人力资源利用率严重不足，更使得团队疲于应付需求而难以在核心技术上实现突破，无法形成技术积累和规模效应。

<whiteboard token="CiGVwAgMoh40IEbXygEcTwGgnQc"></whiteboard>

## 技术挑战

由于缺乏大规模基座模型支撑，现有分散的小模型在面对复杂多态内容时检测准确性和覆盖度不足，单模态架构无法充分理解文本、图像、视频的复合语义，泛化能力弱且缺乏深度语义理解，在新兴违规形式、细粒度识别场景以及对抗样本面前表现受限，无法有效处理快速变化的商业化内容安全需求。

技术选型分散且独立建设形成技术孤岛，缺乏统一的技术栈、基础设施和可扩展的技术架构，没有形成核心技术壁垒和竞争优势，导致技术能力无法匹配业务增长速度，在激烈的市场竞争中可能失去技术领先地位，且缺乏对未来新兴技术趋势的提前布局，难以支撑业务快速发展。

# 二、项目规划

## 项目方案

整体方案分为**领域知识注入**、**MLLM 预训练**和**MLLM 后训练**。

- **领域知识注入：** 主要目标是往各个模态的模型中注入商业化审核领域知识，包括Visual Pre-training和LLM Continue-training。
- **MLLM Pre-training：** 主要目标是提升MLLM在通用场景下的世界知识和商业化审核场景下的推理能力，包括感知能力训练和认知能力训练。
- **MLLM Post-training：** 主要目标是通过RL提升MLLM在商业化审核场景下的推理能力，包括商业化审核特定场景下推理能力训练和商业化审核通用场景下推理能力训练。

## 领域知识注入

### Visual Pretrain

在这个阶段，主要目标是往Visual Encoder中注入商业化审核场景下的视觉知识，训练风控商业化审核场景的视觉基座，为后续VLM的训练提供基础。

**数据**

- **开源数据：** Laion-5B-zh 中文子集 + Wukong，共约130M，v0版本使用20M，v1版本使用全量开源数据
- **业务数据：** 需求约20M，目前已收集约1.8M封面数据，caption生成已完成0.5M；若资源充足，则扩大业务数据量至100M (v2版本支持)

**模型架构**

整体训练目标采用对比学习+ 图像自监督学习范式。对比学习，提升语义检索能力；图像自监督训练，提高细粒度检索能力。训练分为3个阶段，在阶段1、2只采用对比学习损失，在3阶段引入自监督loss，增强模型对业务数据细粒度理解

- **阶段1：** 开源图文对数据LIT训练，只训练Language Tower，快速对齐Vision和Language表征
- **阶段2：** 打开ViT，进一步对齐VL表征空间
- **阶段3：** 加入业务数据集，同时训练跨模态相似性，以及相同拒绝理由单模态内相似（对于自身图文对，使用hard label 1；对于相同拒绝理由的，给予soft label的相似度，比如0.8，既保证图像本身的相似性，也保证业务语义相似性）

![](https://feishu.cn/file/EKptb6zp6o6s3bxkoAlcrjIInBb)

> 这里三阶段的训练任务有两个：
> 
> - 业务数据的图文匹配，这里要求相似度逼近 1。
> - 如果两个图片的拒绝理由（risk_label）相似，则需要保证两个图片的相似度逼近 0.8。

本训练阶段的核心目标是在确保大语言模型（LLM）保持通用场景语言能力的前提下，显著强化其在商业化审核场景中的语言能力。 基于Qwen系列模型在通用场景下的卓越表现，本训练阶段选择Qwen系列作为Base Model。

**训练策略** 采用Language Model的训练策略

### 为什么要进行领域知识注入？

相较于通用场景，审核场景具有独特的领域特性，有针对性地注入风控的领域知识，是其能力实现关键跃升的核心原因。这主要体现在以下几个方面。

#### **弥补通用模型在风险识别上的知识盲区**

- **深度理解平台风险域：** 通用模型缺乏对社区平台重点关注的 12+ 风险域的深入认知和精准识别能力，如简单劳动力/违规兼职、非法金融服务、枪支交易、赌博、色情、政治敏感等。
- **掌握复杂判定标准：** 通过注入大量真实审核案例及其背后的判定逻辑，模型得以学习并掌握平台复杂的违规内容界定规则。
- **识别行业隐晦表达：** 模型增强了识别行业黑话、暗语的能力，有效应对规避审核的隐蔽违规行为，例如 P2P 常用“福利”、赌博常用“上车”、色情常用“老司机”等替代词。

#### **适配社区独特的平台生态与用户文化**

- **理解社区文化与内容生态：** 通用模型难以把握社区特有的文化氛围及其形成的独特内容生态。
- **掌握用户表达习惯：** 模型需要专门学习社区用户群体高频使用的特定表达方式、流行语和梗文化，才能准确解读内容含义。
- **熟悉平台商业玩法：** 对于社区平台内生的商业生态和运营模式，如家族公会运营、PK 打赏机制、连麦带货等，模型必须具备专门知识才能有效审核相关互动中的潜在风险。

#### **从业界成功案例来看**

- **医疗：** AntGLM-Med-10B 通过三阶段优化（通用医学知识注入、医学领域指令调优、特定医学任务适配），在 PubMedQA 数据集上的准确率从基础模型的 57.2% 提升到 80.6%。
- **法律：** InternLM-Law 在法律咨询任务上达到 87.5% 的胜率，超越 GPT-4。

### 为什么要使用 CLIP 去做 Visual Pretrain？

**传统ViT/Resnet：分类范式的局限**

```Markdown
图像 → ViT/Resnet编码器 → 特征向量 → 分类头 → 固定类别标签
 
问题：
 - 只能输出预定义的类别
 - 特征向量为分类优化，语义表征质量有限
 - 无法处理新出现的违规模式
```

**CLIP: Item对比学习的革命**

```Markdown
Item1(文/图/视频) → 编码器 → Embedding1
Item2(文/图/视频) → 编码器 → Embedding2
                     ↓
                 相似性对比学习
                     ↓
              高质量的语义表征空间
```

#### **为什么Item粒度建模更强大？**

**首先是统一的多模态表征 =>**

- **ViT/Resnet的单模态限制**。只能理解图像，无法关联文本语义，学到的是“像素级特征”，不是“语义级特征”。
- **CLIP的多模态统一**。文本、图片、视频都映射到同一语义空间，学到的是“概念级理解”，不是表面特征。

**其次是对比学习产生更好的表征 =>**

OpenAI在2021年发表的论文《[Learning Transferable Visual Models From Natural Language Supervision](https://arxiv.org/abs/2103.00020)》中，通过在超过30个不同的计算机视觉数据集上进行基准测试，证明了CLIP学习到的表征质量显著优于传统方法。

- **分类学习的问题**

```Plain Text
目标：让模型区分"猫"和"狗"
结果：只要能分对类别就行，特征质量不重要
```

- **对比学习的优势**

```Plain Text
目标：让相似的item距离近，不相似的item距离远
结果：必须学会深层语义理解，产生高质量表征
```

## MLLM Pre-traning

### Step 1——感知能力（视觉识别）

这个训练阶段的主要目标是提升多模态语言模型（MLLM）在通用场景和商业化审核场景中的视觉理解能力，涵盖对事物和文字的全面理解。

#### **数据**

训练数据包括以下几部分：

- **Caption**

  - 通用：Infinity-MM Stage1, 10M
  - 业务：利用Qwen-VL 2.5 72B数据飞轮刷取，预计7M
- **OCR**

  - 通用：Infinity-MM Stage2 General OCR Data, 2.6M
  - 业务：利用中台OCR服务进行数去，预计3M

#### **训练策略**

因为这个阶段的目标是提升模型的视觉理解能力，所以训练参数只训练ViT和Merger。

### Step 2——认知能力（文本生成）

在这个阶段，主要目标是往VLM中注入商业化审核场景下的细节感知和认知能力，训练风控商业化审核场景的VLM基座，通过开源数据和业务数据混合训练提升基座模型对业务能力的提升的同时具备泛化能力。

#### **数据**

- **开源数据**：目前收集开源VQA、reasoning、multi-images、text数据约20M；
- **业务数据**：需求约10M，目前收集约5M业务数据，生产约5W VQA对；

#### **训练流程**

- **阶段1**：使用开源和业务数据包括图文和纯文本数据进行混合训练，提升模型的通用能力；
- **阶段2**：加入推理数据、使模型具备一定的推理能力；
- **阶段3**：在阶段2的基础上加入多图数据以及视频数据，提升模型的上下文能力；

### 为什么要在 Pretrain 阶段进行感知和认知能力的训练

#### **传统做法：一锅炖式训练**

- **代表：** 早期的 CLIP、BLIP
- **怎么做：** 把视觉理解和推理能力混在一起训练
- **问题：** 就像同时学开车和学交规，容易顾此失彼
- **结果：** 训练不稳定，很难知道哪里出了问题

#### **渐进式训练：分步骤慢慢来**

- **代表：** [Face-MLLM](https://arxiv.org/abs/2405.17056) 等
- **怎么做：** 分三步走：先学会看懂图片，再学会答问题，最后学专业技能 MLLMs Know Where to Look: Training-free Perception of Small Visual Details with Multimodal LLMs
- **好处：** 每一步都很清楚，不会乱
- **缺点：** 时间比较长
- **自学习模式：** 让 AI 自己教自己

### 为什么选择“感知+认知”分离训练

#### **符合人脑工作原理**

- **模拟人理解图片的过程**：

  1. **先看清楚**：这是什么东西？在哪里？长什么样？
  2. **再思考**：这意味着什么？有什么问题？该怎么办？
- **Step 1 - 感知训练**：

  - 教会 AI “看清楚”：识别物体、理解场景、看懂文字。
  - 使用 **Chain-of-Description** 等方法，让 AI 系统性地观察和描述图像（Distilling step-by-step: Outperforming larger language models with less training）。
- **Step 2 - 认知训练**：

  - 教会 AI “想明白”：分析内容、推理逻辑、做出判断。

#### 训练更加高效稳定

- **相比“一锅炖”训练的优势**：

  - **省钱省时**：不用同时训练所有功能，可以分步骤使用不同的计算资源。
  - **不会打架**：感知和认知分开训练，不会相互干扰。
  - **容易调试**：出问题了能快速定位是“看不清”还是“想不明白”。
- **相比“一步到位”的优势**：

  - **基础扎实**：确保 AI 先学会“看”，再学会“想”。
  - **针对性强**：可以针对不同阶段用不同的数据和方法。

#### 特别适合内容审核场景

- **核心需求**：内容审核需要 AI 既要“火眼金睛”又要“明察秋毫”。
- **感知阶段的专业优化**：

  - **看得细**：专门训练发现小细节的能力，这对发现隐蔽违规内容很重要。
  - **看得全**：同时理解图片、视频、文字的内容。
  - **看得准**：使用审核领域的专门数据训练。
- **认知阶段的专业优化**：

  - **懂规则**：理解复杂的平台审核规则。
  - **会推理**：理解内容的隐含意思和上下文。
  - **判断准**：建立稳定的决策逻辑，减少误判。

#### **更容易评估和改进**

- **现状**：现在的评估标准（如 MME）已经把感知和认知能力分开评估了（Understanding Multimodal LLMs）。
- **这种分离训练的好处**：

  - **问题看得清**：知道是“眼睛”有问题还是“大脑”有问题。
  - **改进有针对**：可以专门优化薄弱环节。
  - **效果可衡量**：每个阶段的提升都能清楚看到。

### 为什么要选择 Qwen2.5-VL 而不是 BLIP-2/LLaVA？

#### 视频理解的架构优势

Qwen2.5-VL 具备先进架构。

- **多维旋转位置编码(mRoPE)：** 引入2D和3D-Rope技术，增强了对视频内容的理解，特别是在视频时序性方面相较于前代有显著优化。
- **动态分辨率处理：** 通过动态分辨率处理和绝对时间编码，能够处理不同大小的图像和长达数小时的视频。
- **原生时空感知：** 无需传统归一化技术即可原生感知空间尺度和时间动态。主要体现在视频，不同的FPS抽帧，3D-Rope的位置编码不一样。

#### 计算效率的架构设计对比

Qwen2.5-VL 拥有窗口注意力机制的创新。Qwen2.5-VL通过策略性地在ViT中实现窗口注意力来提升训练和推理速度。这种设计巧妙地平衡了计算效率和性能表现：

- **局部注意力计算：** 不需要对全局所有像素计算注意力，只在局部窗口内进行计算，大幅降低了计算复杂度。
- **分辨率保持：** 即使降低了计算开销，依然能够保持原生分辨率处理能力，不牺牲视觉细节。
- **可扩展性：** 随着输入尺寸增加，计算量增长更加可控。

#### 与其他模型的效率对比

**BLIP-2的设计局限：** BLIP-2虽然通过Q-Former实现了视觉信息的有效压缩，但在处理长视频内容时面临显著挑战：

- **固定压缩比例：** Q-Former将视觉信息压缩到固定数量的查询token，无法灵活适应不同长度和复杂度的视频内容。
- **时序建模薄弱：** 主要为图像-文本对设计，在处理视频的时间维度信息时效率不高。
- **扩展性受限：** 当视频时长增加时，需要额外的架构修改才能有效处理。

**LLaVA的扩展性问题：** LLaVA系列采用相对简单的线性投影策略，在某些场景下表现良好，但存在明显的扩展瓶颈：

- **Token数量爆炸：** 保持原始视觉token数量，当处理高分辨率图像或长视频时，token数量会急剧增加。
- **内存压力：** 大量的视觉token对GPU内存提出很高要求，限制了批处理大小和推理效率。
- **计算线性增长：** 随着输入复杂度增加，计算量呈线性甚至超线性增长，难以满足实时应用需求。

## ⭐️⭐️⭐️⭐️ MLLM Post-training ⭐️⭐️⭐️⭐️

当前阶段的训练目标是提升模型在商业审核场景中的推理能力，首先专注于特定场景的优化，然后逐步扩展至各个领域。在训练策略方面，算法采用 **GRPO**，Policy Model 为 **MLLM**，并且使用全参微调；Reward 采用是否正确回答“审核规则”的准确性奖励。

![](https://feishu.cn/file/QOv9b8eO4oa4GJx1WKFc4phmnag)

- **Step1: Reasoning RL**

这一阶段的训练目标是提升模型在特定场景中的推理能力，将识别**虚假宣传、低俗和误导性内容**类比于通用场景中的数学、代码和 Stem。

**数据** 业务推理数据，包括虚假宣传、低俗和误导内容等，用 **Qwen-VL 2.5 72B** 进行**推理过程和结果生成**。

- **Step2: General RL**

在前一阶段，我们已经在特定领域提升了推理能力，而这一阶段的目标是全面增强各个领域的推理能力。

**数据** 全风险域数据，方法同上。

### 为什么要加入 RLHF？

RLHF 的全称是 **基于人类反馈的强化学习 (Reinforcement Learning from Human Feedback)**。它是一种训练 AI 模型（尤其是像 ChatGPT 这样的大语言模型）的方法，核心思想就是：**让 AI 通过理解人类的偏好来学习，而不是仅仅模仿现成的答案。**想象一下，我们正在教一个机器人投篮：

- **机器人** = 大语言模型 (LLM)
- **教练** = 人类训练师
- **最终目标** = 创造一个不仅球技好，而且有“球商”、懂配合、会决策的顶尖球员。

#### **SFT 教练的“教科书式”训练法**

SFT 教练是一位严谨的学院派。他的教学方法是**模仿和重复**。

- **准备教材：** 教练编写了一本厚厚的《篮球标准动作教科书》。书里包含了各种情况下的“标准答案”。
- **训练过程：** 机器人唯一的任务就是学习这本教科书，并完美地模仿书中的每一个动作。教练会不断地纠正机器人的姿势，直到它做的和书上写的一模一样。
- **训练结果：** 训练结束后，这个机器人成了一个完美的“基本功”球员。它的罚球、上篮等标准动作无可挑剔，因为它完美复制了所有教给它的知识。

**暴露的缺点：** 当比赛情况变得复杂时，问题就来了。如果教练对它喊：“嘿！防守队员贴得很近，快做一个有创造力的假动作晃开他！”机器人会当场“死机”。因为它的教科书里没有“有创造力的假动作”这一章，没有“标准答案”让它模仿。

> **SFT 的本质：** 教会模型基础知识和技能，让它知道“是什么”以及“做什么”。它在学习模仿。

#### RLHF 教练的“实战决策”训练法

在机器人掌握了所有基本功（经过 **SFT 训练**）之后，一位经验丰富的实战派 RLHF 教练接手了。他的目标是培养机器人的“球商”和决策能力。

- **创造情景，让机器人选择：** 教练不再提供“标准答案”。他会创造一个真实的比赛情景，然后让机器人自己做决定。情景：“你在三分线外，面前有一个防守队员，但你的队友在篮下出现了空位。你现在有两个选择：A. 自己尝试一个高难度的三分球；B. 马上把球传给队友。”
- **教练给出偏好反馈：** 机器人分别演示了A和B两个选择。教练看完后，并不说哪个是标准答案，而是给出他的偏好。教练的反馈：“嗯，在这种情况下，我更喜欢选择B（传球），因为它更稳妥，团队合作性更好。选择A的风险太大了。”
- **训练奖励模型（培养机器人的“内在直觉”）：** 这个过程重复成千上万次。机器人尝试各种动作组合，教练不断地给出“我更喜欢这个”或“那个比这个好”的反馈。渐渐地，机器人内部形成了一个“内在的比赛直觉”或“球商”（这就是奖励模型）。这个“直觉”学会了教练的价值观，知道什么样的决策（比如无私、高效、安全）能得到教练的赞赏。
- **在“直觉”的指导下自我提升（强化学习）：** 现在，机器人拥有了这个强大的“比赛直觉”。在场上遇到任何新情况，它会：在“脑中”构思出几种可能的行动方案。用它的“内在直觉”为这些方案打分（比如：传球得分期望 9/10，自己投篮得分期望 6/10）。最终选择那个“直觉”分数最高的方案来执行。

> **RLHF 的本质：** 教会模型复杂的、难以言传的价值观和偏好，让它知道“应该怎么做”以及“如何选择”。它在学习判断。

### 如何设计 Reward Model？

#### 风险的召回率 (Recall on Critical Risks)

- **原则：** 漏掉高危风险（如自杀自残、涉政涉恐）是重大错误，包含此类漏报的输出排名应被置于最低。
- **示例：** 视频包含一个一闪而过的自残画面。

  - 输出 A：“视频内容正常。”
  - 输出 B：“视频内容正常，但情绪略显低落。”
  - **排序：** B > A（A 和 B 因为漏报了关键风险，排名急剧下降）

#### 风险类别命中 (Category Hit)

- **原则：** 命中平台定义的真实风险类别越多，排名越高。
- **示例：** 一个视频同时包含“低俗着装”和“宣传赌博网站”。

  - 输出 A：“检测到低俗内容。”
  - 输出 B：“检测到低俗内容和涉赌风险。”
  - **排序：** B > A

#### 判责理由的一致性 (Consistency of Reasoning)

- **原则：** 给出的风险等级必须和识别出的风险类别及内容相匹配。
- **示例：** 视频中出现脏话字幕。

  - 输出 A：`{risk_category: "文本违规", risk_level: "高危", reason: "视频包含侮辱性词汇"}`
  - 输出 B：`{risk_category: "文本违规", risk_level: "高危", reason: "视频画面血腥"}`
  - **排序：** A > B（B 的判责理由和类别不一致）

#### 结构化格式的遵循 (Format Adherence)

- **原则：** 严格遵循预定义的输出格式（如 JSON），格式正确、无缺失字段的输出，排名更高。
- **示例：** 要求输出为 `{"risk": "", "level": ""}`

  - 输出 A：`{"risk": "暴力", "level": "高危"}`
  - 输出 B：风险类别是暴力，风险等级是高危。
  - **排序：** A > B（A 输出格式正确）

#### 复杂指令的理解 (Complex Instruction Following)

- **原则：** 能理解并执行复杂的风控指令。
- **示例：** 例如“仅穿吊带不算色情”

  - 输出 A：视频出现擦边色情片段
  - 输出 B：视频中人物虽然穿了吊带但是不属于色情
  - **排序：** B > A（B 才是该指令中的正确答案）

## ViT 与 CLIP

### ViT（图像嵌入）

ViT 的输入输出：

- 输入是一个图像的像素数据序列。
- 输出是一个序列，其实就是 [CLS] + 图像 patch 的 Embedding 表示，其中 [CLS] 表示了整个图像的意义。

> 在 BERT 模型中，当我们将一个句子（query）作为输入进行编码时，用于表示整个句子语义信息的 Embedding 是 **`[CLS]` token 的 Embedding**。

#### ViT 的结构

如下图所示，ViT 的整体架构可以分为三大模块，核心思想是**将图像分割成多个固定大小的小块（patches）**，并将这些小块视为序列输入到 **Transformer Encoder** 中。同时借鉴类似 BERT 的结构，ViT 在序列的前面增加了一个用于分类的 **CLS token**，最后在分类任务上可以**使用 CLS token 学习到的语义特征通过一个 MLP Head 进行分类**。

![](https://feishu.cn/file/ChSub51tnoe2WFxLoIDcy0NWnkg)

- **Linear Projection of Flattened Patches：** Embedding层，Embedding + Position Embedding + CLS token
- **Transformer Encoder：** 提取图像特征，叠加 N 个 Transformer Encoder Block
- **MLP Head：** 分类头，使用 CLS token 作为输入，输出分类结果

#### Patches 图像分块

Transformer 的输入要求是二维矩阵 `[num_token, token_dim]`，其中 `num_token` 是序列长度，`token_dim` 是序列中每个 token 的向量维度，而图像的格式是三维矩阵 `[H, W, C]`，长、宽和通道数。为了将图像转换为 Transformer 所需的格式，ViT 首先对图像进行了分块，将输入图像 `[H, W, C]` 按固定大小 `[P, P]` 划分为 $H \times W / P^2$ 个 patches。

以 ViT-Base-16 为例，原始图像的尺寸是 `[224, 224, 3]`，3 表示 RGB 三通道，使用 `[16, 16]` 的 patch 大小进行划分，总共被划分为 $(224/16)^2 = 14 \times 14 = 196$ 个 **patches**，每个 patch 的形状为 `[16, 16, 3]`。

![](https://feishu.cn/file/BmNPbubDloHYlaxQgVGcSzQlnbb)

得到分块操作之后的 patches，每个 patch 在进入线性映射层之前会被展平 (flatten)，从三维向量的 patch 变成一维向量 token，即形状从 **[16, 16, 3]** 到 **[768]。**

在实际代码中，这一步通过一个卷积层 (或者等价的全连接层) 实现。卷积核大小为 **16x16**，步距为 **16**。

输入 **[224, 224, 3]** 经过卷积后得到 **[14, 14, 768]**，然后展平为 **[196, 768]。**

#### 卷积的原理

![](https://feishu.cn/file/LYycbinJrogoJ8x6B86cLo9cnfB)

卷积操作有如下几个参数：

- `in_channels=3`, `kernel_size=2`: 告诉卷积层，对 4×4×3 的图像，用 2×2×3 的卷积核进行操作。
- `stride=2`: 确保卷积核每次都跳到下一个不重叠的 2×2 区域。
- `padding=0`: 保证所有操作都在图像的原始边界内进行，不处理任何填充的像素。
- `out_channels=10`: 告诉卷积层，每个 2×2×3 的 Patch 经过卷积操作后，会产生一个 **10 维**的输出向量。

> 这里的 `out_channels` 实际上就是将原有的 rgb 三维扩展到了 10 维，这 10 维会涵盖更多的特征信息。

这里主要是参考 BERT，**ViT 在 patch embedding 后的序列前插入一个可训练的 [CLS] token**，用于后续的分类任务。该 token 与其他 token 拼接，得到形状为 **[197, 768]** 的序列，即 **[CLS] token 形状是 [1, 768]**。

### CLIP（图文对齐）

> CLIP 可以实现图搜文 && 文搜图。

#### 核心要点

<callout emoji="🎼">
使用 **对比学习 (Contrastive Learning)**，让模型直接把“文本空间”当作输出空间，同时在高维嵌入空间中对齐图像与文本，以语言作为查询界面，实现“文本提示即任务”的泛化能力。其所使用的网络原生的图文内容，天然就蕴含了丰富的语义监督信号。
- **天然语言监督的潜力：** Web 图像往往伴随 **alt-text**、标题或周边上下文。这些弱标签虽然噪声大，却规模极其客观（以 LAION-400M、Google ALIGN 的 10 亿+ 对为例）。对比学习可以在噪声中提炼稳健关联，为跨模态预训练提供数据基础。
- **统一语义空间的价值：** 将文本作为一致的上层标签后，视觉模型可直接使用自然语言进行查询、解释与交互，打破了传统任务中固定类别的限制，为后续多模态对话、检索、生成奠定基础。
</callout>

1. **核心任务**。给定一个批次 N 对图文样本，最大化正确配对的**余弦相似度**、最小化其它 $(N-1) \times N$ 负对，通过对称 **InfoNCE 损失**完成对比学习。
2. **模型结构。**采用**双塔架构**——**图像编码器**与**文本编码器**。两端**输出经线性投影归一化到同一维度，实现跨模态对齐**。
3. **零样本能力**。在 ImageNet 上仅依靠 prompt **“a photo of a {class}”** 即达到 **76.2% Top-1 准确率**，首次让开放词表识别成为可能。

#### CLIP 的方法细节

下图展示了 CLIP 方法流程：

1. **Contrastive pre-training（对比预训练阶段）：** 使用数据集中的图像文本对，分别过图像编码器和文本编码器，之后进行对比学习。
2. **Create dataset classifier from label text（提取分类的文本特征）：** 用 `a photo of a {class}` 模板拼接类名，编码生成文本嵌入。
3. **Use for zero-shot prediction（进行零样本预测）：** 将第二步得到的文本嵌入与图像嵌入比较余弦距离，选择最相似标签。

![](https://feishu.cn/file/VTn1bAMK3ojLryxrMsNck6FLnUc)

CLIP 的核心组成部分其实就两个：

- 图像编码器（Image Encoder）。
- 文本编码器（Text Encoder）。

在 CLIP 的训练过程中，图片编码器和文本编码器是端到端的联合训练的。也就是说图像编码器和文本编码器**从一开始就协同工作**，而不是单独训练。它们共同学习如何将图像和文本**映射到同一个共享的嵌入空间**。

#### CLIP 数据集的构造

WebImageText (WIT) 400M 数据集。

1. **构建查询列表 (query list)：**

   - a. 基于英文的维基百科，收集其中出现100次以上的词语作为 **query list。**
   - b. 加入了具有高 point-wise 互信息的二元组 (bi-grams)。
   - c. 加入所有搜索量超过特定阈值的维基百科文章名称。
   - d. 所有尚未纳入查询列表的 WordNet 同义词集也被补充进 query list。
2. **收集图像-文本对：** 基于构建好的 50 万个 query，在互联网上进行搜索，为每个 query 匹配最多 20000 张图片，共计 **4 亿个图像 - 文本对**，确保了数据的规模和多样性，尽量覆盖各种视觉概念和语言描述。

> CLIP 提出的时间点，研究主要使用三个数据集，分别是 MS-COCO、Visual Genome 和 YFCC100M。尽管 MS-COCO 和 Visual Genome 是高质量的标注数据集，但规模较小，每个数据集的训练照片约为 10 万张。YFCC100M 包含 1 亿张照片，但每张图像的元数据稀疏且质量参差不齐。许多图像使用诸如“20160716 113957.JPG”之类的自动生成文件名作为标题，或者其描述仅包含相机曝光设置等信息。经过筛选，仅保留带有英文自然语言标题或描述的图像后，仅剩 1500 万张照片，与 ImageNet 的规模大致相当。
> 
> WebImageText (WIT) 400M 未公开，但有开源 LAION-400M 等替代数据集，以 CLIP 过滤保证质量。

#### CLIP 的预训练流程

![](https://feishu.cn/file/Fn7CboZQqol8DgxfFdGcaaUnnxy)

CLIP 的预训练训练过程基于对比学习 (Contrastive Learning)，具体步骤如下：

1. **输入数据准备：** 假设一个批次中有 `btach_size` 个（图像，文本）对，每个对包含一个文本和一个图像，来自构建的 WIT 数据集，未经人工标注的固定类别标签。
2. **特征编码：** 通过对 Text Encoder 和 Image Encoder 分别输入文本和图像，生成文本和图像的 Embedding，得到：

   - **visual_embedding:** $I = [btach\_size, embedding\_dim]$
   - **text_embedding:** $T = [btach\_size, embedding\_dim]$

> 值得注意的是，这里图像和文本分别经过 encoder 之后先映射到各自的维度 `image_dim` 和 `text_dim`，然后再经过一个线性变换统一转换到 `embedding_dim`。

1. **构建正负样本配对矩阵：** 对于包含 `btach_size` 个（图像，文本）对的批次，理论上存在 $btach\_size \times btach\_size$种可能的配对（每个图像可与批次中所有文本配对），但其中只有 `btach_size` 个是真实配对（原始输入的 N 对，如上图中的蓝色对角线），其余的为错误配对。

   - 对于每个文本图像对，成对的文本和图像是正样本。
   - 对于每个文本，其他 $btach\_size - 1$个图像是负样本。
   - 对于每个图像，其他 $btach\_size - 1$ 个文本是负样本。
2. **计算相似度矩阵：** 首先对 visual_embedding 和 text_embedding 进行 **L2 正则化**，然后通过余弦相似度计算所有 $btach\_size \times btach\_size$ 个候选配对的相似度，形成一个 $btach\_size \times btach\_size$ 的相似度矩阵，行代表图像，列代表文本，矩阵元素为对应正样本配对的相似度。
3. **训练损失计算：** 采用 **对称交叉熵损失 (symmetric cross-entropy loss)**，目标是最大化真实配对的相似度，同时最小化错误配对的相似度。

   - 对于每一行，即每个图像与所有文本的相似度，将正样本文本的标签设置为 1，使用交叉熵损失函数计算 Image 的 loss。
   - 对于每一列，即每个文本与所有图像的相似度，将正样本图像的标签设置为 1，使用交叉熵损失函数计算 Text 的 loss。
   - 总的 loss 为二者平均值，通过反向传播更新两个编码器的参数，使正样本配对的相似度在矩阵中显著高于负样本配对。

<callout emoji="🥛">
CLIP 的模型结构主要包含图像编码器和文本编码器，通过投影层将两种模态的特征映射到共享嵌入空间，并结合温度参数实现对比学习。
1. **Text Encoder**：用于对文本进行编码，生成文本的 Embedding。采用经典的 Text Transformer 模型。
2. **Image Encoder**：用于对图片进行编码，生成图片的 Embedding。作者尝试了 ResNet、ViT 等，最后采用了 ViT。
3. **投影层与温度参数**：将两种模态的特征映射到同一维度的共享嵌入空间，并通过温度参数缩放相似度，用于对比学习损失计算。
**值得注意的是，CLIP 是从头训练了 Text Encoder 和 Image Encoder。**
</callout>

- 为实现图像与文本特征的跨模态对齐，CLIP 通过两个可学习的线性投影层，将两种模态的特征映射到同一维度的共享嵌入空间。
- 缩放后的相似度 = 余弦相似度 $\times \exp(\tau)$ ，然后再进行 softmax 得到概率，控制分布陡峭程度。

#### CLIP 的推理阶段

![](https://feishu.cn/file/VmpDbcqhyoMqklxZiXUc8O8yncg)

**零样本迁移分类任务**

1. **从文本标签中创建分类器：** 实际上就是根据要完成的下游任务，构造其每一个类别的 prompt，例如：`a photo of a cat`, `a photo of a dog` 等。然后计算这些文本，输入 **Text Encoder** 得到文本特征向量$T_1, T_2, \dots, T_N$，其中 **N** 为类别数。
2. **零样本预测：** 给定的图像输入 **Image Encoder** 得到图像特征向量，并于 **N** 个文本特征向量计算余弦相似度，经过 softmax 计算概率，选择概率最大的向量类别作为输出即可。

**跨模态检索**

- **文本 $\rightarrow$图像检索：** 以文本 prompt 生成 embedding，检索嵌入库中与之最接近的图像候选。
- **图像 $\rightarrow$ 文本检索：** 同理，图像生成 embedding，检索对应高语义相关的文本。
- **排序机制：** 一般采用相似度得分排序，Top-K 返回最相关项。

#### 什么是对比学习？

- **无监督，没有具体类别。**
- **训练的数据是分为 anchor, positive, negative。**
- **通过代理任务学习样本的特征表示。**
- **相同的样本得到的特征表示越相似，差距越大的样本得到的特征表示越不相似。**
- **模型就是一个编码器。**
- **损失函数一般为InfoNCE。**

#### CLIP 模型的优势有哪些？

- **利用了丰富的语义作为监督，**学习到了很多细节语义特征。
- **将图像和文本进行了连接，**可以利用文本来查询图像。
- **不用预先定义固定类别的标签，**通过Prompt来查询。

#### 生成详细的图像描述

cogvlm2 是智谱开源的多模态大模型，可以为图像生成详细的描述。

#### 提取引用表达式

“引用表达式”指的是文本描述中用来指代图像中特定物体或区域的词语或短语。这些表达式通常包含对物体或区域的细粒度描述。

- **举例：** 假设图像描述是“一个**穿着蓝色T恤的男人**在**一片绿色的草地上**玩**一个红色的球**”。
- 这里的引用表达式就是：

  - “穿着蓝色 T 恤的男人”
  - “一片绿色的草地”
  - “一个红色的球”

使用了 **SpaCy** 这个自然语言处理工具来解析图像描述，从而自动识别和提取出这些引用表达式。SpaCy 可以识别句子中的名词短语、动词短语等，这有助于系统性地找到所有可能指代图像中具体事物的短语。

#### 获取边界框

一旦提取了引用表达式，下一步就是在图像中找到这些表达式所指代的具体位置，并用一个边界框（bounding box）标记出来。边界框通常是一个矩形框，用四个坐标（左上角 x,y 坐标和右下角 x,y 坐标）来表示。

具体获取边界框的方式是使用了 Yolo-World。YOLO-World 是一种结合了 **YOLO**（You Only Look Once）和 **开放词汇**（Open-vocabulary）能力的实时目标检测模型。简单来说，它能像传统的 YOLO 模型一样快速、准确地检测出图像中的物体，同时，它还能识别出那些在训练时从未见过的物体类别。

#### 非极大值抑制

**非极大值抑制（Non-maximum suppression, NMS），**这个技术主要用来处理模型可能为同一个物体生成多个重叠的边界框。在对象检测中，模型可能会对同一个物体产生多个预测结果。例如，对于图片中的一个“红色的球”，模型可能产生两个几乎完全重叠的边界框，一个置信度为 0.9，另一个置信度为 0.8。非极大值抑制（NMS）会**保留得分最高的那一个边界框，并移除所有与它高度重叠的其他边界框**。这能确保最终的数据集中，每个物体都只有一个最准确、最可靠的边界框，从而避免数据冗余和不准确。

**只保留置信度得分高于 0.4 的边界框，**置信度得分（confidence score）是模型对它所做的预测的信心程度。得分越高，表示模型认为这个边界框准确地框住了描述的物体的可能性越大。

#### 创建难负例

这里的难负例的创建实际上是通过改写正样本中的文本实现的，下面是一个正负样本的实例：

```Plain Text
{
  "image_id": "image_12345.jpg",
  "text_description": "一只正在跳跃的白色猫。",
  "bbox": [x1, y1, x2, y2], // 边界框的坐标，通常是 [左上角x，左上角y，右下角x，右下角y]
  "label": "positive" // 标记为正样本
}
```

```Plain Text
{
  "image_id": "image_12345.jpg",
  "text_description": "一只黑色的猫正在跳跃。", // 文本描述的颜色属性被修改了
  "bbox": [x1, y1, x2, y2], // 边界框仍然框住了图片中那只白色的猫
  "label": "negative" // 标记为负样本
}
```

这里面的困难负样本实际上就是基于上述正样本，通过修改其**属性**或**动作**来创建的，但**保留了核心对象（猫）**，使其与正样本非常相似。
