2smart_resize：动态分辨率的第一环

目标：保留长宽比地把图片缩放到 28 的倍数，且 token 数落在预算内。为什么必须是 28？因为 QwenViT 的 patch 是 14×14，merger 再做 2×2 合并——factor = patch_size × merge_size = 14 × 2 = 28，保证后续两级切分都整除。

# blm_clip/data.py —— 移植自 qwen_vl_utils 的官方实现
def smart_resize(height, width, factor, min_pixels, max_pixels):
    # ① 先四舍五入到 factor(28) 的整数倍
    h_bar = max(factor, int(round(height / factor)) * factor)
    w_bar = max(factor, int(round(width / factor)) * factor)

    if h_bar * w_bar > max_pixels:      # ② 超出 token 预算：等比缩小
        beta = math.sqrt((height * width) / max_pixels)
        h_bar = max(factor, int(math.floor(height / beta / factor)) * factor)
        w_bar = max(factor, int(math.floor(width / beta / factor)) * factor)
    elif h_bar * w_bar < min_pixels:    # ③ 低于下限：等比放大（小图也值得被看清）
        beta = math.sqrt(min_pixels / (height * width))
        h_bar = int(math.ceil(height * beta / factor)) * factor
        w_bar = int(math.ceil(width * beta / factor)) * factor
    return h_bar, w_bar

本例：700×525 网页图

round(525/28)×28 = 532？不对——round(525/28)=round(18.75)=19 → 19×28=532；round(700/28)=25 → 700。面积 532×700=372,400 > max_pixels(351,232)，触发等比缩小，最终 672×504（=24×28 × 18×28）。

token 预算的含义

max_pixels = 448×28²，即最多 448 个 merged token（对齐文档业务图 392×224 的规模）；min_pixels = 128×28²，保证最小图也有 128 个 token 的表达能力。

对比传统 CLIP：原版 CLIP 把任意图片强压到 224×224，横图被压扁、细节被抹掉。smart_resize 让"每张图按自己的长宽比被看见"，代价是 token 数变长——这正是后面 packing/binpack 必须存在的原因。

4image_to_qwen_patches：与官方逐一对齐的网格重排

这一步是整个数据通路最容易写错的地方：QwenViT 的 patch_embed 是 Conv3d(kernel=2×14×14)，且 merger 按 2×2 邻域分组，所以输入 patch 的排列顺序必须严格匹配官方的 reshape + transpose 规则，错一个维度，喂给卷积的就是错乱的像素。

def image_to_qwen_patches(img, patch_size=14, merge_size=2, temporal_patch_size=2):
    # 输入 img: [C, H, W]，H、W 均为 28 的倍数（smart_resize 已保证）
    C, H, W = img.shape
    gh, gw = H // patch_size, W // patch_size        # patch 网格：48 × 36

    # ① 图片的 temporal 维为 1，复制成 2 帧以适配 Conv3d 的时间核
    x = img.unsqueeze(0).repeat(temporal_patch_size, 1, 1, 1)   # [2, C, H, W]

    # ② 按 (t, temporal, C, gh/2, 2, 14, gw/2, 2, 14) 切分
    x = x.reshape(1, temporal_patch_size, C,
                  gh // merge_size, merge_size, patch_size,
                  gw // merge_size, merge_size, patch_size)

    # ③ 关键转置：把 2×2 merge 组挪到通道维前面 —— 与官方 processor 完全一致
    x = x.permute(0, 3, 6, 4, 7, 2, 1, 5, 8)

    # ④ 展平：每个 patch 变 1176 维（3通道 × 2帧 × 14 × 14）
    patches = x.reshape(1 * gh * gw, C * temporal_patch_size * patch_size * patch_size)
    grid_thw = torch.tensor([1, gh, gw], dtype=torch.long)
    return patches, grid_thw

5packing 与 binpack：两个层级的"变长治理"

动态分辨率让每张图 patch 数不同，由此产生两级问题，分别由两个机制解决——这是整个 BLM 数据侧设计的精髓：

层级机制解决什么代码位置
batch 内packing消除 padding 浪费（示例中省 43.5% 算力）ClipCollator
step 间binpack每桶 token ≈ bin_token，GPU 利用率稳定binpack.py
# ① packing（ClipCollator）：bin 内所有图的 patch 直接拼接，零 padding
patch_list, grid_list = [], []
for b in batch:
    patches, grid_thw = self._process_image_qwenvit(b["image"])
    patch_list.append(patches)
    grid_list.append(grid_thw)
image_inputs = (torch.cat(patch_list, dim=0),   # 注意是 cat 不是 stack！
                torch.stack(grid_list, dim=0)) # [B, 3] 每张图的 (t,gh,gw)

# ② binpack（binpack.py）：数据侧装箱，一个 bin = 一个训练 step
def online_bin_packer(src, token_fn, bin_token):
    current_bin, current_tokens = [], 0
    for sample in src:
        t = token_fn(sample)
        if current_tokens + t > bin_token and current_bin:
            yield current_bin                # 再加就超预算 → 封箱
            current_bin, current_tokens = [], 0
        current_bin.append(sample)
        current_tokens += t
    if current_bin: yield current_bin        # 尾箱也产出

6QwenViT 内部：Conv3d → 2D-RoPE → 窗口注意力

拼接好的 patch 序列进入视觉塔后发生四件事（全部由 transformers 官方实现完成，这也是选 QwenViT 而非自研 ViT 的原因）：

① Conv3d patch 嵌入

Conv3d(3, 1280, kernel=(2,14,14), stride=(2,14,14)) 把每个 1176 维 patch 映射为 1280 维 token。temporal 核为 2，正好吃掉我们复制的 2 帧。

② 2D 旋转位置编码

按每张图自己的 grid_thw 生成 (h, w) 二维 RoPE——位置编码按图独立，与拼接后的全局位置无关，这是 RoPE 配合 packing 的天然优势。

③ window index 重排

token 和位置编码按窗口 index 重排：窗口内做局部注意力（省算力），少数层做全局注意力；重排在 block 结束后按 reverse_indices 还原。

④ cu_seqlens 分段注意力

flash-attn varlen 接口只计算块对角部分：图 A 的 token 永远 attend 不到图 B。连 mask 都不物化，没有"算了再屏蔽"的浪费。

# blm_clip/models.py —— 我们只需要把官方格式喂进去
class QwenViTVisionTower(nn.Module):
    def __init__(self, model_name, embed_dim, merge_size=2):
        base = _Base.from_pretrained(model_name, low_cpu_mem_usage=True)
        self.visual = base.visual          # 官方视觉塔：patch_embed+blocks+merger
        self.proj = nn.Linear(self.visual.config.out_hidden_size, embed_dim, bias=False)

    def forward(self, pixel_values, grid_thw):
        feats = self.visual(pixel_values, grid_thw=grid_thw)
        # transformers>=5.x 返回 BaseModelOutputWithPooling：
        #   last_hidden_state = merger 前（Σgh·gw, 1280维）
        #   pooler_output     = merger 后（Σgh·gw/4, 2048维）← 取这个
        if not torch.is_tensor(feats):
            feats = feats.pooler_output

7逐图池化 + 投影 + 归一化：向量的诞生

视觉塔输出的是变长的 patch token 序列，而对比学习需要每图一个定长向量。收口的三个动作：

# blm_clip/models.py —— 池化切分 + 投影
# ① 按 grid_thw 算每图 merger 后 token 数：t×gh×gw/4（merger 做了 2×2 合并）
tokens_per_image = (grid_thw.prod(dim=1) // (self.merge_size ** 2)).tolist()
# 本例：1×48×36/4 = 432 个 token

# ② 切回每图，均值池化为一个向量（学习版简化；文档流程图为 attention pooling）
chunks = torch.split(feats, tokens_per_image, dim=0)
pooled = torch.stack([c.mean(dim=0) for c in chunks], dim=0)   # [B, 2048]
pooled = pooled.to(self.proj.weight.dtype)   # bf16 视觉塔 → fp32 投影层对齐

# ③ 投影到共享嵌入空间 + L2 归一化
z = self.proj(pooled)                        # [B, embed_dim=256]
return F.normalize(z, dim=-1)              # 余弦相似度的前提：单位向量

[2048]全局视觉表征
→Linear 2048→256
[256]投影到共享空间
→L2 normalize

为什么必须归一化：InfoNCE 的相似度是余弦相似度，只有向量模长为 1，点积才等于余弦；同时可学习温度 τ（init 1/0.07，clamp exp≤100）在这个归一化空间里缩放 logits，控制 softmax 分布的陡峭程度。

一句话总结：这条链路的设计哲学是——规则部分（resize/重排/拼接/切分）零参数、与官方逐一对齐；学习部分（卷积/Transformer/merger/投影）全部交给预训练权重 + 判别式学习率。动态分辨率的灵活性由 packing/batch 内零浪费 和 binpack/step 间稳吞吐 两个机制兜底，最后用一次池化把变长世界收拢为定长向量。
