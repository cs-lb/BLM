1. 为什么需要细粒度对齐：全局 CLIP 的盲区

标准 CLIP 做的是全局对齐：整张图压成一个向量，整句文本压成一个向量，用 InfoNCE 拉近正样本对。这对"图里有没有猫"这类粗粒度检索很有效，但有一个系统性盲区——模型只要抓住主导物体就能拿高分，完全不需要理解属性、数量、空间关系。

维度全局 CLIP（粗粒度）FG-CLIP（细粒度）
对齐单元整图 ↔ 整句图像区域（bbox）↔ 引用表达式（短语）
监督信号图文对（image-caption pair）区域-表达式对 + 难负例（hard negatives）
典型失败案例"红球"和"蓝球"的相似度几乎一样（词袋效应）通过属性改写的难负例强制区分颜色/动作/数量
损失函数L_global（批内 InfoNCE）L_global + α·L_regional + β·L_hard（α=0.1，β=0.5）
数据成本互联网爬取，噪声大但便宜需要一条自动生产线：描述→抽取→定位→改写
一个直觉例子 给 CLIP 看一张"穿蓝色 T 恤的男人在绿草地上玩红球"的图，再给它两句话：
① "一个穿蓝色 T 恤的男人"  ② "一个穿绿色 T 恤的男人"
全局 CLIP 对两者的打分往往相差无几——因为"男人"这个词主导了相似度。细粒度对齐的目标就是让模型对 ① 显著高于 ②，且这个"高"要能在同一个 softmax 里把 ② 压下去。
面试一句话版本 FG-CLIP 的核心观察：CLIP 的对比学习目标只约束全局语义，细粒度判别信号在训练数据里根本不存在——所以要显式制造区域级监督（grounding）和细粒度负样本（hard negative），用额外的损失项注入到训练里。训练上分两阶段：先全局对齐塑形，再低学习率叠加区域监督防遗忘。

2. 总体架构：一条数据生产线 + 三个训练损失

整个方案分两段：离线数据生产线把普通图文对升级成带区域标注和难负例的细粒度数据；在线训练在原有全局 CLIP 损失上叠加区域级损失。损失设计已对齐 FG-CLIP 论文（式 2~5）。

2.2 训练目标（在线，FG-CLIP 论文式 5）

L = Lglobal + α · Lregional + β · Lhard，　α = 0.1，β = 0.5 L_global：整图-整句对比损失（保住原有能力）；L_regional：区域-表达式的批内对称 InfoNCE（论文式 3）；L_hard：每个区域的 M 条候选描述做单向 softmax 分类（论文式 4，1 正例 + M−1 条属性改写难负例在同一 softmax 竞争）。α、β 为论文消融确定的最优权重。

3. Step 1：Dense Caption 详细描述生成

为什么需要这一步？原始图文对的 caption 通常很短（"一个男人在玩球"），没有属性信息，后面抽不出细粒度表达式。所以第一步用多模态大模型把每张图重新描述一遍，强制覆盖「物体 + 属性 + 动作 + 场景」。论文中这一步对应 CogVLM2-19B 对 LAION-2B 的 16 亿条重写——我们用 Qwen2.5-VL-3B 做同思路的小规模复现。

fg_data/dense_caption.py —— 核心 prompt 与本地后端
# 关键在 prompt 设计：四点要求逼模型输出属性密集的描述
PROMPT = (
    "请详细描述这张图片，要求：\n"
    "1. 列出图中所有主要物体，并说明其颜色、材质、状态等属性；\n"
    "2. 描述物体的动作和相互关系；\n"
    "3. 描述场景环境；\n"
    "4. 输出一段连贯文字，不要列表，不要分点。"   # 连贯文字便于下一步 SpaCy 句法分析
)

class LocalQwenCaptioner:
    """本地 Qwen2.5-VL 后端（3B 已缓存可直接跑；无算力时换 DashScope API）"""
    def caption(self, image_path: str, max_new_tokens: int) -> str:
        messages = [{
            "role": "user",
            "content": [
                {"type": "image", "image": f"file://{image_path}"},
                {"type": "text",  "text": PROMPT},
            ],
        }]
        # apply_chat_template 拼好对话模板，processor 同时处理图像和文本
        text = self.processor.apply_chat_template(
            messages, tokenize=False, add_generation_prompt=True)
        inputs = self.processor(text=[text], images=[image_path],
                                return_tensors="pt").to(self.device)
        with torch.no_grad():
            # do_sample=False：贪心解码，数据生产要稳定可复现，不要随机性
            out = self.model.generate(**inputs, max_new_tokens=max_new_tokens,
                                      do_sample=False)
        # 切掉 prompt 部分，只保留模型新生成的 token
        gen_ids = out[0][inputs["input_ids"].shape[1]:]
        return self.processor.decode(gen_ids, skip_special_tokens=True).strip()

def quality_filter(caption: str, min_len: int = 20) -> bool:
    """质控：过滤过短或模板化失败的描述，宁缺毋滥（噪声会传染到下游所有步骤）"""
    return bool(caption) and len(caption) >= min_len
工程要点 ① 贪心解码保证可复现；② 质控前置——这一步放水的噪声会在"抽取→定位→训练"三级放大；③ 小批量验证先行：python -m fg_data.dense_caption --limit 100 先跑 100 张看效果再全量。批量生产时可用 vLLM 离线批推理把吞吐提升一个数量级（continuous batching + PagedAttention）。

4. Step 2：引用表达式抽取（Referring Expressions）

什么是引用表达式？描述中指代图中特定物体/区域的短语。关键约束：必须带细粒度修饰（颜色/材质/动作/数量），光秃秃的"猫""狗"不算——因为它无法和图中具体区域建立唯一对应。

例子 "一个穿着蓝色T恤的男人在一片绿色的草地上玩一个红色的球"
→ ["穿着蓝色T恤的男人", "一片绿色的草地", "一个红色的球"]
fg_data/expressions.py —— SpaCy 抽取 + 正则兜底
# 代词/无信息量开头直接丢弃——"它"指代不明，grounding 必然产生噪声框
_PRONOUN_HEAD = ("它", "这个", "那个", "这些", "那些", "其", "该")

def extract_with_spacy(caption: str, nlp) -> list[str]:
    """SpaCy 路径：名词短语块（noun_chunks）+ 修饰语过滤"""
    doc = nlp(caption)
    expressions = []
    for chunk in doc.noun_chunks:
        # 规则1：长度≥2，单字名词没有细粒度信息
        if len(chunk) < 2:
            continue
        # 规则2：块内必须含形容词/动词/数词——这是"细粒度"的判定标准
        # "男人"不含 ADJ/VERB/NUM 会被丢弃；"穿蓝色T恤的男人"含 VERB 保留
        if not any(t.pos_ in ("ADJ", "VERB", "NUM") for t in chunk):
            continue
        text = chunk.text.strip()
        if len(text) < 2 or text.startswith(_PRONOUN_HEAD):
            continue
        expressions.append(text)
    return expressions

# 精度较低但保证流水线不断——重要的工程习惯：每个外部依赖都要有降级路径
_ATTR_PATTERN = re.compile(
    r"[一二两三四五六七八九十百千万\d]+[个只张片条双件匹头颗株]?"
    r"[^，。；,.;]{1,12}?"

数量约束 去重后每图保留 3~8 个表达式（默认 1~6）：太少说明 caption 质量差（丢图），太多则训练时区域前向开销爆炸。

5. Step 3：Grounding 边界框定位

这一步把文本短语"钉"到图像像素上：用 YOLO-World（开放词汇检测器，支持任意文本词表）为每个表达式找框。三条质控规则都来自一个原则：宁可丢数据，不要噪声监督。

  • NMS 去重（iou=0.5，模型内置）：同一物体的重复框合并；
  • 置信度 > 0.4：低置信度框大概率是错配，监督信号有害；
  • 无框则丢弃表达式：不退化成"全图框"——全图框等于把区域损失退化成全局损失，还不如没有。
fg_data/grounding.py —— 每个表达式保留最高分框
def ground_one_image(model, image_path: str, expressions: list[str],
                     conf_thres: float, nms_iou: float) -> list[dict]:
    """对一张图的所有表达式做开放词汇检测，返回 [{expr, bbox, conf}]"""
    # set_classes：把开放词表设为本图的表达式列表——
    # YOLO-World 会把每个表达式编码成文本嵌入，检测头对每个词表项独立打分
    model.set_classes(expressions)
    # conf=置信度阈值，iou=NMS 阈值（内置 NMS 在此生效）
    results = model.predict(image_path, conf=conf_thres, iou=nms_iou, verbose=False)[0]

    W, H = results.orig_shape[1], results.orig_shape[0]
    best: dict[int, dict] = {}   # cls_idx（词表下标）-> 最高分框
    for box in results.boxes:
        cls_idx = int(box.cls.item())    # 该框属于词表中第几个表达式
        conf = float(box.conf.item())
        # 同一表达式可能检出多个框，只留置信度最高的一个（每物体一个最准的框）
        if cls_idx not in best or conf > best[cls_idx]["conf"]:
            x1, y1, x2, y2 = box.xyxy[0].tolist()
            best[cls_idx] = {
                "expr": expressions[cls_idx],
                "bbox": [x1 / W, y1 / H, x2 / W, y2 / H],  # 归一化到 [0,1]，与分辨率解耦
                "conf": round(conf, 4),
            }
    return list(best.values())   # 无框检出的表达式自然消失（被丢弃）
为什么存归一化坐标？ 训练时图像会被缩放到不同分辨率（尤其 Qwen2.5-VL 的原生动态分辨率），归一化坐标与输入尺寸解耦，池化时再按实际 patch 网格换算（见第 7 节）。

6. Step 4：难负例构造（Hard Negatives）—— 全流程的灵魂

这是整个方案最关键的一步。核心思想：保留核心对象，只改一个细粒度属性，让负样本与正样本"几乎一样但又确实不同"。在论文式 4 的框架下，每个区域的候选描述 = 1 条正例 + M−1 条难负例，它们将在同一个 softmax 里竞争（见第 8 节）。

改写示例（框不变！） "一只正在跳跃的白色猫" → "一只正在跳跃的黑色猫"（改颜色）
难负例指向同一个 bbox——模型没法靠"找错物体"蒙混，必须学会区分属性。

构造方式采用 LLM 改写 + 质量校验（规则词表作为兜底）：大模型不受固定词表限制，能覆盖开放属性（大小、状态、材质、空间关系……），但 LLM 会跑偏——重写整句、产出不"难"的负例——所以必须配校验器。三道闸门：结构校验（非空/去重/不等于正例）、长度比例约束、编辑相似度 ≥ 0.5（SequenceMatcher，保证"只改一处"）。LLM 产出不足时用规则词表补齐，流水线永不断。

fg_data/hard_negatives.py —— LLM 改写 prompt 与三道校验
LLM_PROMPT = (
    "你是视觉-语言对比学习的数据构造专家。给定一个描述图像区域的中文短语，"
    "请构造 {k} 个“难负例”（hard negatives），用于训练模型区分细粒度属性。\n"
    "要求：\n"
    "1. 每个难负例只改动原短语中的一个细粒度属性（颜色/动作/数量/材质/状态/大小等），"
    "其余文字保持完全不变；\n"          # "只改一处"是"难"的前提：改多处模型很容易判负
    "2. 改动后的语义必须与原短语确实冲突（互斥），不能是近义或无关替换；\n"
    "3. 语句通顺，符合中文表达习惯；\n"
    "4. 难负例之间互不相同；\n"
    "5. 每行输出一个难负例短语，不要编号、不要引号、不要任何解释。\n"
    "原短语：{expr}"
)

def _valid_negative(expr: str, neg: str, used: set[str],
                    min_ratio: float = 0.5) -> bool:
    """单条难负例质量校验（拦截 LLM 跑偏的三道闸门）：
    1. 非空且不等于正例、未使用过；
    2. 长度比例约束：改写只动一个属性，长度不应剧烈变化；
    3. 编辑相似度 >= min_ratio：SequenceMatcher 衡量整体重合度——
       "只改一处"的难负例 ratio 通常 > 0.7；LLM 重写整句时 ratio 显著降低，
       以此拦截"不难"或跑偏的输出。
    """
    if not neg or neg in used:
        return False
    if not (0.4 * len(expr) <= len(neg) <= 2.5 * len(expr)):
        return False
    return difflib.SequenceMatcher(None, expr, neg).ratio() >= min_ratio

def make_hard_negatives(expr, k, rng, llm_maker=None):
    """统一入口：优先 LLM 构造（逐条校验），不足 k 条时用规则词表补齐"""
    negatives, used = [], {expr}
    if llm_maker is not None:
        try:
            for neg in llm_maker.generate(expr, k):
                if len(negatives) >= k:
                    break
                if _valid_negative(expr, neg, used):   # 逐条过闸门
                    used.add(neg)
                    negatives.append(neg)
        except Exception:
            # 单条失败不中断：本条回退规则词表（流水线可靠性优先）
            pass
    if len(negatives) < k:   # LLM 不可用或产出不足 -> 规则补齐
        for neg in make_hard_negatives_rule(expr, k - len(negatives), rng):
            if neg not in used:
                used.add(neg)
                negatives.append(neg)
    return negatives
    # 注意：改不出难负例的区域会被丢弃——没有对比就没有可学信号
实测效果（本工作区 fg_clip，Qwen2.5-VL-3B text-only 生成） LLM 后端复用 dense caption 的模型权重（零额外模型成本），do_sample=True, temperature=0.7 提供改写多样性；编辑相似度校验实测可拦截整句重写（"一朵粉色的花"→"今天天气很好我们去公园散步" ratio≈0.13 被拦）和过短碎片（"红色" 被长度约束拦）。
面试加分点：为什么批内随机负例不够？ 批内负例是"别的图的别的句子"，和正例差异巨大（不同物体、不同场景），模型用粗粒度特征就能轻松分开，梯度趋近于零。难负例只改一个属性，迫使模型把容量分配到细粒度判别上——这就是"hard negative mining"在对比学习里的标准作用。FG-CLIP 论文消融证明：难负例损失是细粒度提升的最大单项贡献（FG-OVD hard 子集 24.5% → 46.1%）。用 LLM 而非规则词表改写，是为了覆盖开放属性空间；但必须配校验器，否则 LLM 的自由度会变成噪声源。

7. 区域特征提取：bbox → patch 网格池化（含错位处理）

数据准备好了，怎么从 ViT 里取出"某个 bbox 的特征"？方案要点：不裁图、不二次编码、不引入检测主干——直接复用整图前向已经算好的 patch token，把 bbox"叠"到 patch 网格上做矩形均值池化。

def _pool_bbox(feat_map: torch.Tensor, bbox: list[float]) -> torch.Tensor:
    """在 [gh, gw, D] 的 patch 特征图上按归一化 bbox 做矩形均值池化"""
    gh, gw = feat_map.shape[0], feat_map.shape[1]
    # 归一化坐标 × 网格尺寸 → patch 下标，clamp 防越界
    x1 = max(0, min(int(bbox[0] * gw), gw - 1))
    y1 = max(0, min(int(bbox[1] * gh), gh - 1))
    # +1 保证小框至少覆盖 1 个 patch（否则小物体池化成空 tensor）
    x2 = max(x1 + 1, min(int(bbox[2] * gw) + 1, gw))
    y2 = max(y1 + 1, min(int(bbox[3] * gh) + 1, gh))
    return feat_map[y1:y2, x1:x2].mean(dim=(0, 1))   # [D]，均值池化

def encode_regions(model, image_inputs, regions_per_image, region_proj):
    """对 batch 内每图的若干 bbox 提取区域特征，返回 [ΣR_i, embed_dim]"""
    if isinstance(image_inputs, (list, tuple)):   # qwenvit 路径（动态分辨率）
        pixel_values, grid_thw = image_inputs
        tower = model.visual.visual
        # 取 merger 之前的 patch token——merger 会 2×2 合并相邻 patch，空间分辨率降 4 倍
        tokens = tower(pixel_values, grid_thw=grid_thw)
        # qwenvit 把所有图的 patch 拍平成一个长序列，按 grid_thw 切回各图
        patch_counts = (grid_thw[:, 1] * grid_thw[:, 2]).tolist()
        per_image = torch.split(tokens, patch_counts, dim=0)
        feats = []
        for tokens_i, (_, gh, gw), bboxes in zip(
                per_image, grid_thw.tolist(), regions_per_image):
            feat_map = tokens_i.view(gh, gw, -1)   # 还原成 2D 网格 [gh, gw, D]
            feats.extend(_pool_bbox(feat_map, b) for b in bboxes)
    else:                                   # timm 路径（固定 224，14×14 网格）
        feats_tokens = model.visual.vit.forward_features(image_inputs)  # [B,1+N,D]
        patch = feats_tokens[:, 1:, :]               # 去掉 CLS token
        gh = gw = int(patch.shape[1] ** 0.5)
        feats = []
        for tokens_i, bboxes in zip(patch, regions_per_image):
            feat_map = tokens_i.view(gh, gw, -1)
            feats.extend(_pool_bbox(feat_map, b) for b in bboxes)

    stacked = torch.stack(feats, dim=0)
    # region_proj：merger 前 hidden 维（1280/768）→ 共享嵌入维（如 768）
    # 用独立投影层而非复用全局投影，因为 patch 均值特征的分布与 CLS 不同
    return region_proj(stacked.to(region_proj.weight.dtype))
追问预案：YOLO 的框和 patch 网格几乎从不对齐，怎么办？ 这是刻意的近似而非疏忽，成立的两条前提：
① patch token 不是"那个格子的像素"——经过多层自注意力，每个 token 编码的是"这块区域在全图上下文中意味着什么"，边界错位从像素层面的硬错位软化为表征层面的软噪声；
② 对比损失只要相对排序——边界错位对所有候选区域是同一种系统性噪声，不偏向任何一边，系统性噪声在对比学习里天然抵消。
取整策略是过度包含（floor 左边界 / ceil 右边界，误差 ≤ 一圈 14px patch）：多圈一点背景被内部占多数的目标 token 稀释，比漏掉目标本体安全。
精度不够时的三档升级路径 ① 取整量化（现版）：覆盖到的 patch 全计入，最简单； ② 覆盖面积加权：w = patch 与 bbox 的交集面积 / patch 面积，r = Σ(wᵢ·tᵢ)/Σwᵢ——边界 patch 从"全票"变"按比例投票"，一行思路零依赖； ③ RoIAlign（FG-CLIP 论文版）：分数坐标双线性插值采样，完全消除量化误差——像素级任务（分割/小目标）才值得上，对属性级对齐，①与③的差距在检测框本身的抖动噪声量级以下。

8. 三个损失（FG-CLIP 论文版）：L_global + 0.1·L_regional + 0.5·L_hard

本节三项损失与 FG-CLIP 论文式 2~5 一一对应。两阶段训练：Stage 1 只训全局（基座 v1 已完成）；Stage 2 三项联合，学习率比 Stage 1 低 1~2 个数量级（论文 1e-4 → 1e-6），防止细粒度训练冲掉全局能力。

8.1 L_global：全局对比损失（守基本盘）

Lglobal = −(1/2N) Σi [ log softmax 相似度（图→文）+ log softmax（文→图） ] 批内 N 对图文的对称对比损失（论文式 2，InfoNCE 形式）。作用一个字：守——区域监督是额外打补丁，没有它约束，细粒度训练会把全局检索能力带崩，所以周期 eval 盯的恰恰是全局 hit@5 而非区域指标。

8.2 L_regional：区域-表达式对称 InfoNCE（论文式 3）

Lregional = −(1/2K) Σi=1..K [ log es(rᵢ,lᵢ)/τ/Σj es(rᵢ,lⱼ)/τ + log es(lᵢ,rᵢ)/τ / Σj es(lᵢ,rⱼ)/τ ] K = batch 内全部有效框（每图 ≤4）。r 是区域特征（第 7 节的网格池化 + region_proj），l 是对应表达式特征，τ 与全局损失共享。它教的不再是"整图像这段文字"，而是"这个框里的东西就是这个词"——区域定位能力。

8.3 L_hard：难负例 M 路单向 softmax 分类（论文式 4，本次升级的核心）

Lhard = −(1/K) Σi=1..K log [ es(rᵢ, lᵢ,₁)/τ / Σj=1..M es(rᵢ, lᵢ,ⱼ)/τ ] 每个区域的 M 条候选描述（j=1 为正例，j>1 为 M−1 条属性改写难负例）放进同一个 softmax 竞争，模型必须把概率质量压到正例上。单向（区域→文本）即可，因为难负例只在文本侧构造。
对比维度旧版：margin hinge（max(0, m+s_hard−s_pos)）论文版：M 路 softmax 分类（当前实现）
梯度特性分对即零梯度（hinge 截断），样本"毕业"后不再学习正例与所有难负例持续竞争，每条难负例恒有梯度
分数校准只约束相对间隔，跨样本分数不可比（"比烂"空间）同一 τ 下的 softmax 归一，分数跨样本可比、可设阈值
多负例利用每条难负例独立与正例比，互不知情M−1 条难负例在同一分母里互相压制，梯度信号更强
论文消融证据—FG-OVD hard 子集 24.5% → 46.1%（+88%），三项中贡献最大

8.4 损失代码（当前实现）

fg_clip/region.py —— 区域 InfoNCE + 论文式（4）M 路分类
def region_infonce_loss(region_z, expr_z, logit_scale):
    """区域-表达式批内对称 InfoNCE（输入需已 L2 归一化）"""
    logits = logit_scale.exp() * region_z @ expr_z.t()   # [K, K] 相似度矩阵
    labels = torch.arange(logits.shape[0], device=logits.device)  # 对角线为正例
    # 对称：区域→表达式 + 表达式→区域，两个方向各算一次交叉熵
    return 0.5 * (F.cross_entropy(logits, labels)
                 + F.cross_entropy(logits.t(), labels))

def fgclip_hard_loss(region_z, cand_z, cand_counts, logit_scale):
    """难负例 M 路 softmax 分类损失（FG-CLIP 论文式 4，单向）：
        L = -(1/K) Σ_i log [ exp(s(r_i, l_i,1)/τ) / Σ_j exp(s(r_i, l_i,j)/τ) ]

    每个区域的 M_i 条候选描述（第 0 条正例 + M_i-1 条属性改写难负例）放进
    同一个 softmax 竞争。相对 margin hinge 的优势：
      - 正例与所有难负例持续竞争，每条难负例都贡献梯度（hinge 分对即零梯度）；
      - 分数经同一 τ 标定，跨样本可比（缓解"比烂"/校准问题）。

    参数：
        region_z:    [K, D] 区域特征（已归一化）
        cand_z:      [ΣM_i, D] 候选描述特征，按区域连续排布，每区第 0 条为正例
        cand_counts: [K] 每个区域的候选数 M_i
        logit_scale: 共享温度（与全局/区域 InfoNCE 同一个 logit_scale）
    """
    tau = logit_scale.exp()
    losses, offset = [], 0
    for i, m in enumerate(cand_counts.tolist()):
        logits = tau * (cand_z[offset:offset + m] @ region_z[i])      # [M_i]
        target = torch.zeros(1, dtype=torch.long, device=logits.device)
        losses.append(F.cross_entropy(logits.unsqueeze(0), target))
        offset += m
    return torch.stack(losses).mean()
数值自测（已通过） 随机特征下 K=3、M=[3,2,1]：L_hard = 0.44 ≈ ln(M) 的期望量级（0.60，τ 锐化后略低属正常）；正例与区域特征完全对齐时 L_hard = 0.0001（趋零）；区域特征 / 候选文本 / τ 三路梯度全部流通。
温度共享的设计 三项损失共用同一个可学习 logit_scale：全局、区域、难负例的相似度用同一把"尺子"度量，避免各损失项在数值尺度上打架——这也是 α、β 能直接沿用论文值（0.1 / 0.5）的前提。

9. 完整训练循环（带注释）

FG 阶段为单卡设计：区域/难负例监督都在 batch 内的区域对上进行，不依赖全局负例，无需多卡负例同步。

train_fg.py —— FGCollator：每区候选描述连续排布
def __call__(self, batch):
    global_batch = self.clip_collator(
        [{"image": self._load(b), "text": b["text"]} for b in batch])

    # ---- 区域监督：每区候选 = [正例 expr, 难负例1, 难负例2, ...] 连续排布 ----
    # FG-CLIP 式（4）要求每区第 0 条为正例；pos 即各区候选首条，无需单独编码
    regions_per_image, cand_texts, cand_counts = [], [], []
    for b in batch:
        bboxes = []
        for r in b["regions"]:
            bboxes.append(r["bbox"])
            cand_texts.append(r["expr"])          # 第 0 条 = 正例
            cand_texts.extend(r["hard"])          # 后接 M-1 条改写难负例
            cand_counts.append(1 + len(r["hard"]))
        regions_per_image.append(bboxes)

    cand_enc = self._tokenize_list(cand_texts) if cand_texts else None
    return {
        **global_batch,
        "regions_per_image": regions_per_image,
        "cand_ids": cand_enc["input_ids"] if cand_enc else None,
        "cand_mask": cand_enc["attention_mask"] if cand_enc else None,
        "cand_counts": torch.tensor(cand_counts, dtype=torch.long),
    }
train_fg.py —— 训练主循环节选
while step < tc["max_steps"]:
    for batch in train_loader:
        regions_per_image = batch.pop("regions_per_image")  # [B][R_i][4] 归一化 bbox
        cand_ids  = batch.pop("cand_ids").to(device)
        cand_mask = batch.pop("cand_mask").to(device)
        cand_counts = batch.pop("cand_counts").to(device)
        batch = move_batch_to_device(batch, device)

        with torch.autocast(device_type="cuda", dtype=torch.bfloat16, enabled=use_bf16):
            # ---- ① 全局损失：整图-整句，保住原有 CLIP 能力 ----
            img_z, txt_z, scale = model(batch)
            l_global = clip_loss_fn(img_z, txt_z, scale)

            # ---- ② 区域损失：共享视觉塔但多一次前向（取 merger 前 token）----
            region_z = F.normalize(
                encode_regions(model, batch["image_inputs"],
                               regions_per_image, region_proj), dim=-1)

            # 候选描述一次文本塔前向；各区首条即正例（cumsum 切片），省一次编码
            cand_z = model.encode_text(cand_ids, cand_mask)
            starts = torch.cumsum(cand_counts, dim=0) - cand_counts
            pos_z = cand_z[starts]
            l_region = region_infonce_loss(region_z, pos_z,
                                           model.clamped_logit_scale())

            # ---- ③ 难负例 M 路分类损失（FG-CLIP 式 4，单向 softmax）----
            l_hard = fgclip_hard_loss(region_z, cand_z, cand_counts,
                                      model.clamped_logit_scale())

            # ---- 总损失（论文式 5）：α=0.1, β=0.5 ----
            loss = (l_global + tc["lambda_region"] * l_region
                    + tc["lambda_hard"] * l_hard) / tc["accum_steps"]

        loss.backward()
        if accum % tc["accum_steps"] == 0:
            # region_proj 的参数也要参与梯度裁剪
            torch.nn.utils.clip_grad_norm_(
                list(model.parameters()) + list(region_proj.parameters()),
                tc["grad_clip"])
            optimizer.step(); scheduler.step()
            optimizer.zero_grad(set_to_none=True)

            # 周期评估：重点监控全局 hit@5 是否回退——
            # 细粒度监督不能损害原有粗粒度检索能力，这是验收红线
            if evaluator and step % tc["eval_every"] == 0:
                metrics = evaluator.run()

10.3 已知简化（诚实边界，面试主动说）

  • 区域池化用取整量化（patch 粒度 14px），论文用 RoIAlign——属性级对齐足够，像素级任务需升级（可先上覆盖面积加权）；
  • 区域特征与全局前向分开执行（多一次视觉前向），工业版可共用一次前向取多层特征；
  • 难负例校验是编辑相似度 + 长度约束（字符串级），工业版可再加独立 judge 模型做语义级校验；
  • YOLO-World 对中文表达式 grounding 能力有限，可将表达式翻译成英文再检测；
  • 数据规模远小于论文（12M 图 / 40M 框），结论外推需谨慎。

10.4 面试话术（30 秒版 + 追问应对）

30 秒版 "标准 CLIP 只做整图对整句的全局对齐，细粒度判别信号在数据里就不存在。FG-CLIP 的思路是显式制造监督：多模态大模型生成 dense caption，SpaCy 抽带属性修饰的引用表达式，YOLO-World 定位边界框，LLM 改写难负例（只改一个属性 + 编辑相似度校验）；训练分两阶段——先全局对齐塑形，再以低一个数量级的学习率叠加三项损失：全局 InfoNCE 守基本盘、区域对称 InfoNCE 教定位、难负例 M 路 softmax 分类教属性判别，权重 α=0.1/β=0.5 来自论文消融。区域特征直接在 ViT merger 前的 patch token 网格上做 bbox 池化，零额外检测参数；难负例分类让正例与所有改写负例在同一 softmax 持续竞争，分数可跨样本校准。"
可能追问回答要点
为什么 L_hard 用 M 路分类而不是 margin？hinge 分对即零梯度，M 路 softmax 让正例与所有改写负例持续竞争、每条负例恒有梯度；且同一 τ 下分数跨样本可比可设阈值，缓解 margin 的"比烂"问题。论文消融显示 hard 项是细粒度提升最大单项（24.5%→46.1%）。
bbox 和 patch 网格对不齐怎么办？取整量化是刻意的过度包含近似：自注意力让 token 表征带全局上下文，错位是软噪声；对比损失只要相对排序，系统性噪声同向抵消。升级路径：覆盖面积加权 → RoIAlign。
为什么 Stage2 要降学习率？细粒度监督会扰动已学好的全局空间，论文 Stage2 比 Stage1 低 100 倍（1e-4→1e-6）防遗忘；我们折中低 10 倍起步，配合周期 eval 盯全局 hit@5 回退。
为什么不直接训练检测器？目标是对齐不是检测；patch 池化复用 CLIP 视觉塔，无额外参数、无检测标注成本，且特征天然在同一嵌入空间。
grounding 错了怎么办？三道闸门：conf>0.4 阈值、无框丢表达式、无区域丢整图。宁可数据少不要监督错——错框的负梯度比没梯度更糟。
和 GLIP / RegionCLIP 的区别？GLIP 是检测框架做短语定位（检测范式）；RegionCLIP 用 RPN 提案蒸馏 CLIP（两阶段）；FG-CLIP 是在对比学习框架内加区域监督，不改模型结构。
LLM 构造难负例怎么保证质量？prompt 约束"只改一个属性且互斥"只是软约束，必须配硬校验：结构（非空/去重）+ 长度比例 + 编辑相似度（SequenceMatcher≥0.5 拦截整句重写）；产出不足用规则词表补齐。工业版可再加 judge 模型做语义级校验。
