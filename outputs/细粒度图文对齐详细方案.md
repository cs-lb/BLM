# 细粒度图文对齐（FG-CLIP 式）详细实现方案

> 基于《风控大模型 BLM 预训练》文档「细粒度的图文对齐」一节展开，补全工程实现细节。
> 参考代码：https://github.com/360CVGroup/FG-CLIP

---

## 1. 背景与目标

### 1.1 为什么需要细粒度对齐

标准 CLIP 的对称 InfoNCE 只优化「整图 CLS embedding ↔ 整句文本 embedding」的对齐，存在两个盲区：

1. **属性/动作盲区**：模型只需学到"图中有一只猫"即可分开正负样本，"白猫还是黑猫、跳还是卧"对 loss 无影响，细粒度信号被全局池化平均掉；
2. **区域盲区**：违规内容常以小区域形式出现（角落二维码、一闪而过的违规帧），全局表征对局部区域不敏感。

风控场景的拒绝理由之间往往只差细节（"低俗着装" vs "正常穿搭"、"广告宣传" vs "正常分享"），因此需要把监督粒度从「图-句」下沉到「区域-短语」。

### 1.2 目标

| 目标 | 说明 |
|---|---|
| 主目标 | 提升 BLM ViT 的 patch 级/区域级表征质量，服务细粒度检索 |
| 下游收益 | ① 难负例 KNN 挖掘更准；② 图搜文 hit@5 提升；③ 抬高 MLLM 感知训练（Step1）起点 |
| 不做什么 | 不改变 CLIP 主流程结构，仅作为阶段3的增强损失接入 |

### 1.3 在主流程中的位置

```
阶段1 LIT → 阶段2 放开 ViT → 阶段3 业务数据（+自监督 +soft label +【细粒度对齐】）
                                                              ↓
                                                        BLM ViT v1
```

---

## 2. 总体架构

细粒度对齐 = **一条区域级监督数据生产线** + **一组区域级对比损失**。

```
原始图片
   │
   ├─(1) cogvlm2 生成详细图像描述（dense caption）
   │
   ├─(2) SpaCy 抽取引用表达式（Referring Expressions）
   │
   ├─(3) YOLO-World 开放词汇检测 → 边界框
   │      └─ NMS 去重 + 置信度过滤（>0.4）
   │
   ├─(4) 区域-文本对数据集
   │      ├─ 正样本：(区域框, 原始引用表达式)
   │      └─ 难负例：(同一区域框, 改写属性/动作后的表达式)
   │
   └─(5) 训练：全局 InfoNCE + 区域对比损失 + 难负例损失
```

## 3. 数据生产线（五步）

### Step 1：生成详细图像描述

- **工具**：cogvlm2（智谱开源多模态大模型，可本地部署）；学习版可用 Qwen2.5-VL-7B + vLLM 替代。
- **要求**：描述必须包含**物体 + 属性 + 动作 + 场景**，避免"一只猫"式的粗粒度输出。
- **Prompt 示例**：

```
请详细描述这张图片，要求：
1. 列出图中所有主要物体，并说明其颜色、材质、状态等属性；
2. 描述物体的动作和相互关系；
3. 描述场景环境；
4. 输出一段连贯文字，不要列表。
```

- **质控**：过滤过短（<20 字）或模板化的描述；抽 1% 人工抽检。
- **量级**：跟随阶段3业务数据，学习版 5~10 万张，工业版随业务封面量（百万级）。
- **吞吐参考**：7B 模型 + vLLM，单卡约 2~4 张/秒，10 万张约 8~14 小时。

### Step 2：提取引用表达式（Referring Expression）

- **工具**：SpaCy（中文用 `zh_core_web_trf`，英文用 `en_core_web_trf`）。
- **定义**：描述中指代图中特定物体/区域的名词短语，通常带细粒度修饰。
- **例子**：描述"一个**穿着蓝色T恤的男人**在**一片绿色的草地上**玩**一个红色的球**"
  - 引用表达式：① 穿着蓝色T恤的男人 ② 一片绿色的草地 ③ 一个红色的球

- **实现**：

```python
import spacy
nlp = spacy.load("zh_core_web_trf")

def extract_referring_expressions(caption: str) -> list[str]:
    doc = nlp(caption)
    expressions = []
    for chunk in doc.noun_chunks:          # 名词短语块
        # 只保留带修饰语（形容词/定语）的短语——纯"猫""狗"不含细粒度信息
        if len(chunk) >= 2 and any(t.pos_ in ("ADJ", "VERB", "NUM") for t in chunk):
            expressions.append(chunk.text)
    return expressions
```

- **质控**：每图保留 3~8 个表达式；丢弃代词开头（"它""这个"）和过短（<2 字）的片段。

### Step 3：获取边界框（Grounding）

- **工具**：YOLO-World（开放词汇实时检测），优势：能检测训练时未见过的类别——正好匹配引用表达式的开放词表特性。
- **流程**：以引用表达式为 text prompt，对原图检测，得到候选框 `[x1, y1, x2, y2]` 与置信度。
- **NMS（非极大值抑制）**：同一表达式可能产出多个重叠框，保留置信度最高者，移除 IoU 大于阈值（如 0.5）的其余框——保证每个物体只有一个最准的框。
- **置信度过滤**：**只保留 score > 0.4 的框**（文档口径）；低于 0.4 视为定位失败，该表达式-图对丢弃。
- **兜底**：表达式无框检出时，丢弃该表达式而非退化使用全图框（避免引入噪声区域监督）。

### Step 4：构造难负例

**核心思想**：保留核心对象，只改一个细粒度属性或动作，使负样本与正样本"几乎一样但又确实不同"。

- **改写规则**（按优先级）：
  1. **颜色属性**：白→黑、红→蓝（从属性词表中随机替换为同类异值词）；
  2. **动作**：跳→卧、跑→坐（动词反义/互斥表）；
  3. **数量**：一个→三个；
  4. **材质/状态**：干净→破损。
- **工具**：学习版用规则词表替换即可；工业版可用 LLM（Qwen2.5-7B）做"最小改动改写"并校验句法通顺。

- **数据格式**：

```json
{
  "image_id": "image_12345.jpg",
  "text_description": "一只正在跳跃的白色猫。",
  "bbox": [x1, y1, x2, y2],
  "label": "positive"
}
{
  "image_id": "image_12345.jpg",
  "text_description": "一只黑色的猫正在跳跃。",
  "bbox": [x1, y1, x2, y2],
  "label": "negative"
}
```

- **配比**：每个正样本配 1~3 个难负例；难负例 : 批内随机负例 ≈ 1 : 4。

### Step 5：产出数据集与格式

- 存储格式：webdataset 分片，每条样本 = `{image, caption（全局）, regions: [{bbox, expr, label}...]}`；
- 区域坐标归一化到 `[0, 1]`，随图resize时同步缩放，避免增强后错位；
- 数据增强约束：**禁用随机裁剪/水平翻转之外的强几何增强**，翻转时同步翻转 bbox 坐标。

## 4. 模型侧改造

### 4.1 区域特征提取

ViT 输出的是 patch token 序列 `[N_patch, D]`，区域特征直接从 patch token 上取，**不额外引入检测主干**：

```python
def region_feature(patch_tokens, bbox, grid_size):
    """
    patch_tokens: [H/14 * W/14, D]  ViT 最后一层输出（不含 CLS）
    bbox: 归一化 [x1, y1, x2, y2]
    做法：将 bbox 映射到 patch 网格，取覆盖 patch 的均值池化（或 attention pool）
    """
    gx1, gy1 = int(bbox[0] * grid_size[1]), int(bbox[1] * grid_size[0])
    gx2, gy2 = int(bbox[2] * grid_size[1]) + 1, int(bbox[3] * grid_size[0]) + 1
    region_tokens = patch_tokens.view(*grid_size, -1)[gy1:gy2, gx1:gx2]
    return region_tokens.mean(dim=(0, 1))          # [D]，再经共享投影层归一化
```

- 动态分辨率下 `grid_size` 随图变化，由 `grid_thw` 直接给出，与 binpack 兼容；
- 区域 embedding 与全局图 embedding **共用同一个投影层**，保证在同一嵌入空间。

### 4.2 文本侧

- 引用表达式过文本塔，取 [EOS] 处表征 + 文本投影层，与 CLIP 推理一致；
- 表达式短（2~10 字），可与全局 caption 拼 batch 一起前向，不增加额外推理次数。

## 5. 损失设计

总损失 = 全局 CLIP 损失 + 区域对比损失 + 难负例加权项：

$$\mathcal{L} = \mathcal{L}_{global} + \lambda_1 \mathcal{L}_{region} + \lambda_2 \mathcal{L}_{hard}$$

建议初始值：$\lambda_1 = 0.5$，$\lambda_2 = 1.0$（难负例是细粒度的核心信号，权重给足）。

### 5.1 全局损失 $\mathcal{L}_{global}$

标准对称 InfoNCE（含阶段3的 soft label 扩展），不变。

### 5.2 区域对比损失 $\mathcal{L}_{region}$

批内所有区域-表达式对做 InfoNCE。设批内有 M 个 `(区域 r_i, 表达式 e_j)`：

$$\mathcal{L}_{region} = -\frac{1}{M}\sum_i \log \frac{\exp(\cos(r_i, e_i)/\tau)}{\sum_j \exp(\cos(r_i, e_j)/\tau)}$$

对称地加 expression→region 方向，取平均。τ 与全局损失共用可学习 logit_scale。

### 5.3 难负例项 $\mathcal{L}_{hard}$

难负例与正例**同区域、异文本**，本质是区域条件下的文本判别，用带 margin 的排序损失或并入 InfoNCE 分母均可：

$$\mathcal{L}_{hard} = \frac{1}{M}\sum_i \max\big(0,\ m + \cos(r_i, e_i^{hard}) - \cos(r_i, e_i)\big)$$

- margin $m$ 初始 0.2；
- 若并入 InfoNCE 分母（难负例作为额外 negative 列），实现更简单，学习版推荐。

```python
def fg_loss(region_feat, pos_expr_feat, hard_expr_feat, logit_scale, margin=0.2):
    s_pos  = cos_sim(region_feat, pos_expr_feat)          # [M]
    s_hard = cos_sim(region_feat, hard_expr_feat)         # [M, K] K个难负例
    logits = torch.cat([s_pos.unsqueeze(1), s_hard], dim=1) * logit_scale.exp()
    return F.cross_entropy(logits, torch.zeros(len(logits), dtype=torch.long))
```

## 6. 训练配置

### 6.1 工业版（对齐文档）

| 项 | 配置 |
|---|---|
| 接入阶段 | 阶段3（业务数据注入），与 soft label、自监督 loss 联合训练 |
| 基座 | QwenViT + 文本塔（阶段2产出） |
| 批大小 | 全局 4k~16k（多卡负例同步 bidir），区域对每图取 3~8 个 |
| LR | ViT 1e-5（layer-wise decay 0.75），文本塔 5e-5，cosine |
| 精度 | bf16 + gradient checkpointing |
| Epoch | 业务数据 1~2 epoch |

### 6.2 学习版（单卡 / 消费级 GPU）

| 项 | 配置 |
|---|---|
| 数据 | 5~10 万张图，区域对约 30~60 万 |
| 批大小 | 图文 256/step + 梯度累积 8 → 有效 2048；区域对每图取 4 个 |
| LR | ViT 1e-5，文本塔 5e-5，warmup 500 步 |
| 时长 | 单卡 H800 约 2~3 小时；24G 消费卡约 8~12 小时（缩小模型至 ViT-B 规模） |

## 7. 评估方案

细粒度能力必须有**独立评估集**，不能只看全局 hit@5：

| 评估项 | 做法 | 通过标准 |
|---|---|---|
| 属性判别准确率 | 构造 `(区域, 正/负表达式)` 对，模型打分判正负 | 相对无 FG 训练的 baseline +5% 以上 |
| 细粒度检索 | 查询文本带属性（"红色的球"），检同对象异属性图 | 正确属性图排序显著靠前 |
| 全局能力回退检查 | 标准图搜文 hit@5 | **不低于** FG 训练前（防止区域损失损害全局表征） |
| 嵌入可视化 | t-SNE 观察同对象异属性样本的分离度 | 属性维度出现可解释聚类方向 |

消融实验：① 去掉难负例只留区域对齐；② 去掉区域对齐只留难负例；③ 全量。验证两项各自的贡献。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| YOLO-World 定位噪声（0.4 阈值仍可能有错框） | 抽样人工质检；错框率高的类目提高阈值到 0.5 |
| 难负例改写产生语病/语义不变（"白色"→"雪白"） | 词表限定反义互斥对；LLM 改写后加相似度校验（与原句编辑距离≥2 且语义确实冲突） |
| 区域损失过强导致全局表征退化 | $\lambda_1$ 从 0.1 起 warmup 到 0.5；监控全局 hit@5 回退 |
| 区域监督计算开销（每图 3~8 个区域） | 区域特征复用 patch token 均值池化，几乎零额外前向成本；仅文本塔多过几条短句 |
