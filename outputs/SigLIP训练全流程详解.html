2binpack：让每步 token 数恒定

动态分辨率下每张图 token 数不同，逐 shuffle 组 batch 会让每步总 token 在 500~1100 间抖动——显存按峰值预留、step 时间不稳、DDP 慢卡拖快卡。binpack 在数据侧装箱，每桶（=一个 step）总 token ≈ bin_token。

bin_token 的计价口径

448 = 392/14 × 224/14，最大业务图的 patch token 数。bin_token = 448×N 即"每桶容纳 N 张满配业务图"。双卡 4090 取 448×32 = 14336（24GB 显存反推）；8×H800 取 448×64 = 28672（文档业务口径）。

在/离线两策略

在线（业务）：尺寸有上限、分布集中 → 流式贪心塞满即封箱，损耗 ≤1 张图/bin；离线（开源长尾）：先统计全量 token 数（结果缓存 .tokencache.json），shuffle 后 binpacking.to_constant_volume 全局装箱，填充率更高。

# blm_clip/binpack.py —— 在线组 bin（业务口径）
def online_bin_packer(src, token_fn, bin_token):
    current_bin, current_tokens = [], 0
    for sample in src:
        t = token_fn(sample)                     # 按文件头尺寸估算 patch token 数
        if current_tokens + t > bin_token and current_bin:
            yield current_bin                    # 再加就超预算 → 封箱
            current_bin, current_tokens = [], 0
        current_bin.append(sample)
        current_tokens += t
    if current_bin: yield current_bin            # 尾箱也产出

# train.py —— DDP 各 rank 交错取 bin：每桶 token 一致 → 两卡 step 时间对齐
bins = bins[rank::dist.get_world_size()]

3packing 与双塔编码

每个 bin 进入模型前由 BinCollator 打包：所有图的 patch 直接拼接（零 padding），文本按 batch 内最长 padding。图间隔离不靠 mask 张量，而是 grid_thw 推出的 cu_seqlens 边界表——注意力按段计算（块对角），图内部按 8×8 patch 窗口做 window index 重排注意力。

4SigLIP 损失：每格一个独立二分类

logit_ij = τ · cos(f_i, g_j) + b
L = − (1/N) Σ_ij log σ( z_ij · logit_ij )，z_ij = +1(配对) / −1(非配对)

与 InfoNCE 的本质区别：InfoNCE 的分母是整行 softmax 归一（任何 key 变化都耦合整行梯度）；SigLIP 把 N×N 矩阵的每个格子当独立二分类——任意 key 的去留不影响其他格子。这带来三个工程红利：loss 可按 query 行局部计算（多卡无需全局归一）、小 batch 更鲁棒、τ+b 双参数比单温度更稳定。

负偏置 b=−10 的作用：矩阵中负对远多于正对（N²−N vs N），b=−10 让初始 logits 大幅偏负——正对要"爬坡"（训练初期正对 loss 大、负对≈0），防止负对被轻易压到 σ≈1 后梯度消失。实测：随机双塔 loss≈10.6，完美对齐 loss≈ln2≈0.69。
# blm_siglip/losses.py —— 本地 query 行 × 全局 key 列
logits = logit_scale.exp() * query_z @ key_all.t() + logit_bias   # [n, Ng]
labels = -torch.ones_like(logits)                        # z=−1 默认负对
pos_cols = torch.arange(n) + rank * max_n                # 本卡正例在全局的列位置
labels[torch.arange(n), pos_cols] = 1.0
pair_loss = -F.logsigmoid(labels * logits)               # 逐格 sigmoid
pair_loss = pair_loss * key_mask.unsqueeze(0)            # 剔除填充 key 列（见下）
return pair_loss.sum() / n                               # 按本地 query 数平均

5多卡负例同步：变长 gather-with-grad

目标：每卡 query 看到全局负例（2 卡 ×2、8 卡 ×8），但编码算力各付各的——传的是 ~12KB 的 embedding 副本，不是原始数据。binpack 下各 bin 图片数不同（rank0 可能 10 张、rank1 只有 9 张），NCCL all_gather 要求形状一致，所以是变长 gather：

# blm_siglip/losses.py —— 变长负例同步（三步）
# ① 交换各卡样本数（world 个 int32，通信量可忽略）
counts = gather_counts(n, img_z.device)        # 如 [10, 9]
max_n = max(counts)                            # 10

# ② 零填充对齐后 all_gather，本卡位换回带计算图的真身
class _GatherWithGrad(torch.autograd.Function):
    def forward(ctx, local_tensor, counts):
        padded = cat([local_tensor, zeros(max_n - n_local, D)])  # 尾部补零
        dist.all_gather(gathered, padded)
        gathered[ctx.rank] = padded            # 本卡份保留计算图（要回梯度）
        return torch.cat(gathered, dim=0)       # 他卡份是常量副本（只当 key）
    def backward(ctx, grad_output):
        start = ctx.rank * ctx.max_n
        return grad_output[start:start + ctx.n_local], None  # 只回本卡有效行

# ③ 无效 key 列（填充行）用 mask 剔除出损失——数值验证：填充换成全1巨型相似度，loss 分毫不差
mask[r * max_n : r * max_n + counts[r]] = 1.0

前向：rank1 数据在哪

只出现在 loss 的 key 列（两个方向各一次）：i2t 里 txt_z¹ 占列、t2i 里 img_z¹ 占列，扮演"额外负例候选"。

反向：梯度怎么分

query 侧梯度完整回本卡；key 侧只有本卡真身那几行回梯度；他卡副本无梯度——他卡应得的梯度由它自己对称领取，最后 DDP all-reduce 平均汇合。

6超参数与训练循环

项值理由
优化器AdamW(β=0.9/0.98, eps=1e-6)CLIP 系惯例，β2=0.98 对大 batch 对比更稳
视觉塔 / 文本塔 LR1e-5（wd=0.2）双塔均预训练，小 LR 保护表征
投影层 + τ/b LR5e-5（wd=0）新参数大 LR；标量加 wd 会扭曲语义
调度器linear warmup 200 步 + cosine防初期大梯度冲乱预训练权重
梯度累积2 步（有效 batch ≈ 40 对）补偿 bin_token 砍半的负例缺口
梯度裁剪 / 精度1.0 / bf16 + 梯度检查点24GB 显存前提（见第 7 章）
总步数5000（≈2 epoch）9.9 万样本 ÷ ~20 对/step
# engine.py —— 一步训练的实际顺序
with torch.autocast(device_type="cuda", dtype=torch.bfloat16, enabled=True):
    img_z, txt_z, logit_scale, logit_bias = model(batch)      # 各卡独立编码本 bin
    loss = loss_fn(img_z, txt_z, logit_scale, logit_bias) / accum  # gather+SigLIP
loss.backward()                                  # 梯度切回本卡份；检查点重算激活
if micro % accum == 0:                          # 每 2 个 micro-step 才更新
    grad_norm = clip_grad_norm_(model.parameters(), 1.0)  # 裁剪+记录范数
    optimizer.step(); scheduler.step()           # DDP 已自动 all-reduce 平均梯度
    optimizer.zero_grad(set_to_none=True)

7显存账：bin_token 怎么按显存反推

组成计算大小
固定开销视觉 bf16 1.4G + 文本 fp32 2.3G + 梯度 3.7G + AdamW m+v 7.1G~14.5GB
视觉激活（检查点）32 层 × T × 1280 × 2B + 反向重算工作区≈ T × 125KB
文本激活（检查点）24 层 × (n×96) × 1024 × 2B较小
bin 规模token 数 T峰值显存结论
448×32（dual_4090 采用）14,336~17GB✅ 24GB 安全
448×64（8×H800 档）28,672~19GB✅ 80GB 从容
448×128（4090 天花板）57,344~24GB⚠️ 极限
448×320143,360~35GB❌ 4090 放不下 / ✅ H800
调参原则：显存不炸的前提下 bin_token 尽量大（负例更多、填充率更高），同时填充率 ≥95%；24GB 场景务必开梯度检查点（+30% 计算换激活减半以上）。

产物位置内容
checkpointoutputs/dual4090_v0/ckpt_step{N}.pt模型+optimizer+config（轮转保留 3 个）；视觉塔部分即 BLM ViT v1
metrics.jsonl同目录每 20 步：loss/lr/τ 与 b 轨迹/grad_norm/吞吐；评估结果同文件
train.log同目录完整控制台输出（tee 双写）
最终评估训练结束自动跑i2t/t2i R@1/5/10 + hit@5

健康信号

① 初始 loss ≈ 10.6（负偏置主导）随后持续下降；② τ 缓升、b 从 −10 回升；③ 双卡 it/s 一致、显存接近（binpack 生效）；④ 500 步 hit@5 显著超过随机基线 0.5%。

异常排查顺序

NCCL 卡住 → 查两卡 bin 数一致性；OOM → 确认 grad_checkpointing 已开 → 降 bin_token；loss 不降 → 看 metrics.jsonl 的 grad_norm 爆炸或归零。
